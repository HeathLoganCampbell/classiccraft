# 0024. Chat over the existing packet pipeline

- **Status:** Accepted
- **Date:** 2026-10-20
- **Deciders:** Heath Logan Campbell
- **Tags:** networking, ui

## Context

The GPU client was single-player: it never created a `NettyClient`, so there was no
transport for chat and no way to see other players. The shared packet handler also
referenced `client.Minecraft` directly, which the GPU client cannot load.

Chat additionally needs text input and text rendering in a client with no AWT text
pipeline.

## Decision

- **Protocol:** `ChatMessagePacket` (registry id 7) carries a sender and a message as
  UTF-8 length-prefixed strings. The client sends only the text; the server stamps
  `sender` from the `PlayerConnection`'s player and broadcasts the packet to every
  connection, including the author. There is no local echo while connected.
- **Decoupling:** `common.network.ClientBridge.View` exposes `getWorld()`,
  `addEntity(...)` and `onChatMessage(...)`. `Minecraft` and `GpuMain` install
  themselves; the packet handler no longer references the applet client.
- **Connection:** `NettyClient` takes host, port and username, and `connect()` returns
  false instead of throwing. The GPU client connects only with `--server host[:port]`
  and falls back to single-player. Block edits go through `Player.packetSink`, and the
  player's position is sent once per simulated tick.
- **UI:** `ChatOverlay` rasterises the 5x6 bitmap font into a 413x56 RGBA texture only
  when the text changes; `blit.frag` alpha-composites it over the bottom of the frame.
  `T` or `/` opens the input, `Enter` sends, `Esc` cancels, and movement keys are
  released while typing.

## Alternatives considered

- **`Graphics2D.drawString`** - rejected: antialiasing, platform fonts and an AWT
  surface in a GLFW/OpenGL window.
- **A glyph-quad renderer** - rejected for this version: more GL objects and draw calls
  for a handful of lines. The texture upload is cheap and only happens on change.
- **Local-only chat** - rejected: it does not message other players.

## Consequences

**Positive**

- Chat works between any number of clients through the existing framing and registry.
- The packet handler is now usable by any client, not just the applet.
- Text stays crisp at the internal resolution and costs nothing while idle.

**Negative**

- Broadcast only: no direct messages, ignoring, rate limiting or moderation.
- Other players are still not rendered (the GPU path has no sprite pass), so chat is the
  only evidence of them.
- The font is uppercase-only and lacks some punctuation; unsupported characters render
  as `?` and spaces advance without a glyph.
- The font must not be loaded through the legacy `Bitmap` loader: it creates a
  `Graphics2D`, and initialising AWT inside the GLFW run loop deadlocks
  `glfwPollEvents` on macOS. `ChatOverlay` reads the atlas with `ImageIO` + `getRGB`
  instead.
- The client sends positions at up to 60 Hz, which is more than the 20 TPS server needs.

**Neutral**

- Chat history is in-memory only and capped at six lines on screen.
